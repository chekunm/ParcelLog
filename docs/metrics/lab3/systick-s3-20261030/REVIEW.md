1153 завершені FLASH-маркери, 888 фронтів PIR, режим MODE=1 на кожному фронті. Декодер дроту знайшов 888 рядків nearby_motion; у кожному інтервалі між послідовними фронтами є рівно один рядок. Це не доводить відсутність втрат поза записом чи правильність кожної причинної асоціації. У 756 інтервалах є рівно один RESPONSE, у 132 — декілька.

Лише два фронти перебували всередині FLASH-маркера: 8.004268950 і 19.743863400 с. Перший має один наступний RESPONSE до наступного фронту і nearby_motion seq=11; час до RESPONSE 16.878850 мс. Другий має два RESPONSE до наступного фронту і nearby_motion seq=22; найближчий RESPONSE через 78.979800 мс, але зв'язок неоднозначний. Обидва рядки мають mode=storage. Навіть якщо прийняти обидва як кандидати, це менше необхідних 30; 30 успішних випадків не доведено. Результат відображає тестові імпульси генератора, не фізичні спрацювання PIR. FLASH-маркер включає невдалу спробу HAL erase і сканування; стирання або фізичний flash stall не підтверджено.

Не повторювати S1/S2. Наступний обмежений S3 можливий лише після окремого GUI-допуску: той самий ELF, підготувати розклад із фазовим охопленням між операціями і фронтами, один короткий запуск до 3 хв плюс перевірка наявного VCD. Результат залежить від невідомого співвідношення wall/model часу та зайнятості команд; 30 збігів не гарантовано. Не змінювати MCU й не вставляти штучну затримку. За недостатньої кількості чесно зафіксувати межу, не повторювати безкінечно. Доступні відмови: в одному обмеженому окремому запуску imuaddr 0x69 → status → 0x68 → status з підтвердженням UART; stuck SDA та фізичний power-cut не називати перевіреними без фактичної ін'єкції.
