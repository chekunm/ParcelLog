# Фактично виявлені проблеми

Нижче наведено факти інтеграції та діагностики.

| Симптом | Підтверджена причина | Виправлення / стан |
|---|---|---|
| Перша інтеграційна збірка не компілювала parser | hook meter_add опинився між if та else, runtime.c:119 | Переміщено після повної гілки; host і ARM збірки повторено. build-first.log і host-first.log збережено. |
| .RamFunc HAL опинилась у FLASH як orphan section | Cube linker script не включав .RamFunc у RAM load/copy region | .RamFunc додано в .data, startup переносить її разом із даними; перевірено секції ELF. Це не усуває загальний flash stall. |
| Перша оцінка flash була занижена на 56 bytes | lab3_memory.py сумував перелік секцій без orphan .RamFunc | Загальний flash load береться з text+data arm-none-eabi-size; map і -A збережено. |
| Лінк майже вичерпав 28 KiB коду | Реальні journal/metrics і printf разом із HAL займають більшу частину C031 | MCU не змінено. Виділено 4 KiB архіву, linker зупинить переповнення. Фактичний запас у memory.json; це чинне обмеження, не завершене виправлення. |

Один запуск coverage також побачив обрізану Python-строку у bind mount, тоді як наступне читання файлу було повним. Повторний той самий запуск пройшов. Root cause не встановлено, тому це не оголошено доказаною помилкою коду або Docker.

У власному pilot f5c3597 є фактична проблема progression: після одного sample UART передає startup дуже повільно і відповіді на команди не підтверджені. Перший великий TX gap починається42,504150ms. Причину не встановлено; b804713 діагностує WFI окремо від TIM3/UART. Не вважати цей симптом доказом несправної flash або виміряною CPU latency.

Виміряна збірка має окремий source manifest і ELF SHA256 2b22b7cc8a8a7a47687667399a58bd45a28b6be3d93b43c37b479bc78aabe6b2. Вбудований build ID ідентифікується окремо від source manifest. ERASE у Wokwi повертав помилку; причина не встановлена.
